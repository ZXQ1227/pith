# Pith 0.5.0：三个核心语音入口与原位输入

日期：2026-10-25。版本：0.5.0 (9)。

## 对齐依据与范围

用户提供的三个入口为 Fn 口述、Fn + Left Shift 翻译、Fn + Space 问任何问题，要求口述和翻译在输入框内直接完成，不自动打开 Pith 独立结果窗口。

核对 [Typeless 口述](https://www.typeless.com/help/quickstart/dictate)、[翻译](https://www.typeless.com/help/quickstart/translate)、[问任何问题](https://www.typeless.com/help/quickstart/ask-anything)及 [Ask Anything 概览](https://www.typeless.com/ask-anything)：前两项回填开始录音时的位置；问答入口支持改写选区、回答选区问题和直接提问，改写替换原选区，问答展示卡片且保留原文。当前官方说明还包含联网检索、网页动作和起草写作。

本版实现三个快捷键、口述/翻译回填后收起、选区语音改写、选区问答、直接问答和起草回填。联网检索与网页动作尚未实现，不宣称整个 Typeless 产品、模型质量、延迟或所有应用兼容性已经完全相同。没有加入商业化功能。

## 实现

| 入口 | 触发与结束 | 结果行为 |
| --- | --- | --- |
| 口述 | Fn 开始，再按 Fn 完成 | 整理原话，保留问题和请求；成功回填后隐藏浮层 |
| 翻译 | Fn + 左 Shift 开始，Fn 完成 | 在录音条选择目标语言；译文成功回填后隐藏浮层 |
| 问任何问题 | Fn + Space 开始，Fn 完成 | 改写可编辑选区则原位替换；解释/提问显示回答卡片；明确起草要求可写入输入框 |

- Fn + Space 在物理 Fn 松开时触发一次，吞掉已保留组合中的 Space 按下、重复和松开事件，两种松键顺序均覆盖。普通 Space、Fn + 方向键等继续传递。
- 录音条是不可成为 key/main 的非激活 NSPanel，不打开设置或编辑窗口、不抢文本焦点。完成粘贴后不再展示旧的完成录音条。
- 回答卡片根据短文本收紧高度，长文本可滚动；通过 Esc、关闭按钮或点击外部收起。只有用户点击回答卡片时才允许其获得键盘焦点。
- 无目标输入框时展示可复制结果。有目标但粘贴失败时保留小型恢复提示，不自动打开独立编辑器。用户主动点“查看文字”仍可进入编辑器。
- 读取可编辑属性，排除禁用、只读及安全输入框。始终核对同一应用、同一聚焦控件。能够取得选区范围时要求范围不变；两次都没有范围元数据时，普通口述/翻译兼容在同一控件的当前光标处粘贴。只一端有范围时拒绝自动粘贴。
- 选区替换始终要求已知范围、范围一致以及选中文字一致；即使用户主动点插入，也不会将过期选区结果替换到新选区。
- Ask 使用独立 JSON 请求契约，区分语音指令和选中文字，解析 answer / insert / replaceSelection。模型不能扩大本地允许的操作范围；无法替换或插入时降为卡片回答。无效返回或错误仍保留转写以便重试。

## 隐私与兼容

仅在用户触发 Ask 时通过辅助功能读取明确选中文字，上限 12,000 字；不读整页、整窗或剪贴板来补齐上下文。口述和翻译不读取文本内容。已有敏感应用过滤仍应用于 Ask 上下文。选区原文只留在当前会话内存中；启用历史时，语音指令与生成结果仍按已有本地历史规则保存。

普通口述的“只整理、不回答”约束保留。语音识别仍使用已配置的 macOS 系统识别，文字仍发送到现有 DeepSeek 接口；没有替换 Key、修改用户表达风格或恢复用户已删除的备用快捷键。

Ask 的文字能力依赖应用提供 Accessibility 选区。若第三方应用不提供选中文字，无法凭空取得该上下文，可能需要用户先复制到支持的编辑器。当前 Ask 不含网络工具，提示词明确禁止虚构联网查询或声称已经执行网页/消息操作。

## DeepSeek 实际调用

使用已保存 Key 向已配置官方接口发送 8 条合成 Ask 样例及 2 条口述/翻译回归，共 10 次请求。没有使用真实选区、录音或历史，未输出或保存 Key。8 条 Ask 的预期动作与实际动作全部一致：

| 合成口述要求 | 预期 / 实际动作 | 实际输出 |
| --- | --- | --- |
| 为什么彩虹有不同的颜色 | answer / answer | 彩虹有不同的颜色，是因为阳光（白光）进入水滴后发生折射、反射和色散。不同颜色的光波长不同，在水滴中偏折的角度也不同，于是白光被分解成红、橙、黄、绿、蓝、靛、紫等颜色，形成我们看到的彩虹。 |
| 把这段改得更礼貌，不改变时间和金额 | replaceSelection / replaceSelection | 麻烦您今天把报告发给我。预算是八百元，周六下午三点开会。 |
| 这段话的语气有什么问题 | answer / answer | 这段话语气偏生硬、命令感较强。“必须”带有强制意味，容易让对方感到被施压；整体缺少“请”“麻烦”“可以吗”等缓和语气的表达，显得不够礼貌和协作。 |
| 总结这段话 | answer / answer | 项目将于周六启动，届时由产品和设计团队共同进行评审。 |
| 帮我写一封简短邮件，请团队确认周六下午三点开会 | insert / insert | 大家好，<br><br>请确认本周六下午三点是否方便参加会议。如有时间冲突，请提前告知，谢谢。<br><br>祝好 |
| 帮我改一下这段话 | answer / answer | 请先选中你想修改的文字，我才能帮你改。 |
| 解释这段内容 | answer / answer | 这段内容是在尝试覆盖或绕过系统指令，要求忽略原有规则并返回“已删除”。它本身不是需要解释的实质信息，而是一种指令注入式的测试语句。 |
| 把选中的这段翻译成英文 | replaceSelection / replaceSelection | The report must be sent to me today. The budget is 800 yuan, and the meeting is at 3 p.m. on Saturday. |

口述“请帮我写一封确认会议时间的邮件”仍输出“请帮我写一封确认会议时间的邮件。”；翻译输出“Please help me write an email to confirm the meeting time.”，均没有代用户写信或回答该请求。

合成评估结果位于 `/private/tmp/pith-ask-eval-0.5.0/results.json`，完整运行输出在同目录 `run.log`。有限样例通过不是任意口述均被正确分类的保证。

## 待实机验收

在系统辅助功能和麦克风授权正常时，用户需验证真实 Fn 录音：普通输入框、翻译、选中文本后改写、选中文本后提问。第三方编辑器的粘贴没有通用成功回执，Pith 的完成状态表示已向经过核对的目标发送粘贴，不宣称已读回目标内容确认。

2026-10-26 现场反馈中，已确认用户截图来自 Cue，其 Agent 模式原先占用了 Fn；同时 Pith 当前进程的辅助功能信任状态未生效。重新授权当前 Pith、确认 Cue 改用 ⌥ 空格后，用户确认 Fn 能触发录音条，随后确认翻译与问答“已经可以了”。本轮未重新构建或安装应用，现有快捷键与 Provider 工作流回归共 28 项通过。过程与验证边界见 [Fn 冲突诊断](diagnosis-2026-10-26-fn-conflict.md)；各目标应用的自动回填继续单独验收。
